# PyCharm 验证记录

本页汇总 2026-10-08 至 2026-10-31 的多论坛、排版与验证等待检查，取代三份阶段性记录。这里只记录已有证据，不代表声明支持的全部 IDE 与操作系统均通过端到端验收。当前安装包及校验值见[项目下载表](../../README.md#下载)。16.3 的复现与验收见文末“16.3”一节；16.2 及更早的待测状态保留为过程记录。

## 当前行为

- 四站统一导航、主题 URL 规范化、历史、收藏及游客边界；拒绝携带凭据的 URL 和非 HTTP(S) 协议。跨论坛相同数字主题 ID 不会串站，分页与别名链接会去重。
- 统一正文、标题、元信息、代码的字体与间距；修复隐藏身份元素后的空列、固定宽度、浮动及正文列表层级，保留图片原色。
- Cloudflare 自动刷新不能被当成验证成功，也不重置首次等待期限。NodeSeek 45 秒、其他论坛 20 秒后提示手动操作，保留真实验证页面与脚本；提供重新验证和停止验证。成功的主文档响应结束验证并恢复阅读布局。
- 页面导航不经插件的请求处理器。验证页由标题或地址中的 `__cf_chl_` 参数识别，验证页内不执行任何插件脚本；重新验证、刷新与重试都重新请求去掉验证参数的地址。
- 四个论坛的主题都能加密分享：LINUX DO 保持 v=2 并与 VS Code 互通，其余论坛使用带站点字段的 v=3。

早期硬超时方案会停止验证脚本，阻碍稍后出现的复选框；16.1 已用上述手动提示替代该方案。

## 16.3（2026-10-30 至 10-31）

用户反馈 V2EX 以外的论坛都卡在 Cloudflare 验证页，且只有 LINUX DO 能分享。日常 PyCharm 2026.1.4（进程外 JCEF 137）的日志与此相符：10-30 17:58 起 linux.do 连续 5 轮返回 `403 cf-mitigated: challenge`，约 9.5 分钟后才得到 200；循环期间 Cookie 库中没有 `cf_clearance`。

### 复现方法

为不影响正在运行的日常 IDE，复现全部在隔离沙箱中进行：PyCharm 2026.1.4，独立 config/system，进程内 JCEF 137，与日常相同的自动代理（系统代理）。另开 JCEF 调试端口，由只读记录器只启用 Page、Network、Target 三个 CDP 域，不启用 Runtime，不注入脚本。URL 只记录路径与参数名，Cookie 只记录名称。对照组为同一网络下全新配置的 Chrome 156，以及一个不装任何插件处理器的裸 JBCefBrowser。

### 结果

| 运行 | 变体 | 结果 |
| --- | --- | --- |
| A1、A2、A3 | 16.2 原包，LINUX DO | 3/3 循环：首个文档即 403 验证；每轮 Cloudflare 都通过 XHR 下发 `cf_clearance`，页面随即重载，带着该 Cookie 仍被返回 403。A1 在验证复选框完成后（约 253 秒）才放行，A2、A3 在观察期内未通过 |
| B0、B0b | 16.2 仅去掉主框架资源处理器，其余（含脚本注入）不变 | 2/2 首个文档 200，10–17 秒完成，无验证页 |
| C1 | 裸 JBCefBrowser | 首个文档 200，无验证页 |
| D1 | 全新 Chrome 156 | 首个文档 200，无验证页 |
| A4、A6、A5、B0c | IDC Flare、NodeSeek（16.2 与 B0） | 均无验证页，说明这两站当时不设验证，不能区分变体 |

另外，A1、A2 冷启动时插件的首次导航都没有发出，30 秒后报“加载超时”：导航调用早于 JCEF 初始化完成，直接调用 `CefBrowser.loadURL` 的请求被丢弃。

根因：16.2 为读取 `cf-mitigated` 响应头，给每次主框架导航都挂了 `CefResourceRequestHandler`，使导航改走 CEF 的拦截通道。在 LINUX DO 上，这让 Cloudflare 每次导航都要求验证，也不承认刚下发的 `cf_clearance`。NetLog 显示两种路径的请求头取值相同，只有 `accept-language` 的位置不同（挂处理器时反而与 Chrome 一致），因此 Cloudflare 依据的具体信号尚未确定；结论以 A/B 结果为准。

### 16.3 修复

- 主框架导航不再挂资源处理器，只保留拦截登录类写请求的处理器。验证页改由标题（“Just a moment…”“请稍候…”）或地址中的 `__cf_chl_` 参数识别；没有这些特征的 403/503 等待 1.5 秒后显示错误页，等待期间不会停止页面加载。
- 验证页内不执行任何插件脚本：探针、加载遮罩、阅读样式和小游戏都会被跳过，并在日志中记录 `page script skipped`。删除每轮验证都要执行的撤遮罩脚本。
- 刷新、重试和导航一律通过 `JBCefBrowser.loadURL` 加载去掉验证参数的地址。浏览器创建前的导航会被延后执行，不再丢失；POST 结果页上 `reload()` 什么也不做的问题（CEF #1420）也不再出现。
- 提示栏和状态栏显示验证轮次，日志记录每轮验证的导航方式与最终放行耗时。
- 加密分享：LINUX DO 保持 v=2；NodeSeek、V2EX 和 IDC Flare 使用 `v=3&site=…`，导入时按站点重建地址并复核。Discourse 的 `/t/编号/楼层` 规范化为对应主题，过去被误当成“slug 为编号的主题”。
