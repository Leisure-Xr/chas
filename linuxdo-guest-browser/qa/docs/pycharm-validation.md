# PyCharm 验证记录

本页汇总 2026-10-08 至 2026-10-14 的多论坛、排版与验证等待检查，取代三份阶段性记录。这里只记录已有证据，不代表声明支持的全部 IDE 与操作系统均通过端到端验收。当前安装包及校验值见[项目下载表](../../README.md#下载)。

## 当前行为

- 四站统一导航、主题 URL 规范化、历史、收藏及游客边界；拒绝携带凭据的 URL 和非 HTTP(S) 协议。跨论坛相同数字主题 ID 不会串站，分页与别名链接会去重。
- 统一正文、标题、元信息、代码的字体与间距；修复隐藏身份元素后的空列、固定宽度、浮动及正文列表层级，保留图片原色。
- Cloudflare 自动刷新不能被当成验证成功，也不重置首次等待期限。NodeSeek 45 秒、其他论坛 20 秒后提示手动操作，保留真实验证页面与脚本；提供重新验证和停止验证。成功的主文档响应结束验证并恢复阅读布局。

早期硬超时方案会停止验证脚本，阻碍稍后出现的复选框；16.1 已用上述手动提示替代该方案。

## 实际页面证据与边界

PyCharm 2026.1.4 / JCEF 137 中已确认：自动等待结束后仍可见验证复选框；停止、重试和重新验证可用；验证中切换 V2EX 返回 HTTP 200，提示隐藏，隐私布局稳定。10-14 日常 IDE 重启后的 V2EX 页面也已核对截图与 `LEXIAO_READER_STATE=stable` 日志。

同一系统代理下，新 Chrome 配置自动进入 IDC Flare 列表；JCEF 137 与独立测试的 JCEF 150 需要手动验证。这不能证明 PyCharm 的 IDC Flare 正文访问成功。代理未完成该验证后的列表、正文、返回及刷新验收；用户随后确认“可以了”并要求提交打包，按用户确认交付。

Windows、2026.3 和四站完整实时链路仍缺少本轮验证证据。`runs/0.2.0/`、`runs/0.3.0/` 是历史矩阵，不能作为 16.1 的结果。
