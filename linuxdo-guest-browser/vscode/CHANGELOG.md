# 更新记录

## 0.19.0 / PyCharm 0.13.0

- 修复浏览历史漏记：VS Code 对缺失或非 ASCII 的 Discourse slug 回退为 `topic`，不再丢弃已成功打开的主题；PyCharm 监听 JCEF 主框架地址变化，覆盖 Discourse SPA 在不触发完整页面加载时的主题跳转。
- 两端新增本地收藏夹。用户可以创建、重命名和删除多个目录，把公开主题收藏到任意目录，并支持搜索、打开、复制 URL 和从目录移除；同一主题可放入多个目录，目录内自动去重。
- 收藏只保存目录名、公开主题标题、规范 URL 和收藏时间，不保存帖子正文、Cookie、User-Agent 或登录状态。

## 0.18.0

- 修复站点限流（HTTP 429）时的阅读中断：正文缓存此前只存在于内存里，重载窗口后就清空，因此冷启动撞上限流会直接掉到整页「暂时无法加载」，而不是既有的陈旧内容加倒计时横幅——`isUsableStaleCache` 承诺的 6 小时回退实际只在同一个窗口会话内有效。
- 已读页面的公开 JSON 现在以单个快照文件写入插件存储目录（最多 80 条 / 4 MB，单条上限 512 KB，保留 6 小时，与陈旧回退窗口一致）。重启 VS Code 后限流时仍可直接显示上次内容。
- 快照在成功响应后去抖 10 秒写入，并在插件停用时落盘；读取是懒加载的，不在激活路径上等待磁盘，也不为每个缓存项创建文件。定时器 `unref`，不会拖住宿主进程退出。
- 新增 `linuxdoGuest.persistContentCache`（默认开启）；关闭时立即删除已写入的快照文件。阅读器历史界面的「全部清除」现在同时清除浏览历史和该快照。
- 冷却时长、退避阶梯、令牌桶节奏和图片缓存策略均未改动；图片仍然只缓存在内存中，不写入磁盘。

## 0.17.0

- 修复长期存在的限流根因：头像和帖子正文图片此前是 webview 里的 `<img>` 直连，绕过令牌桶、请求队列和冷却，也不带游客参数，打开一次列表页会瞬间并发几十个请求。
- 头像默认不再加载，改为首字母色块，可用 `linuxdoGuest.showAvatars` 恢复。关闭时页面 CSP 直接去掉 `https:` 图片来源，从浏览器层面杜绝失控请求。
- 帖子正文图片改由扩展代理：独立的图片令牌桶（流畅每 1.5 秒、均衡每 3 秒、稳妥每 6 秒）、最多 2 并发、只在滚动进入视口时请求，并共享冷却、临时保护与服务器预算。正文里的 emoji 图片直接渲染为文本。
- 图片结果在扩展宿主内存中缓存（最多 120 条 / 24 MB LRU），不写入磁盘；单张上限 1.5 MB。图片的 403 只影响这一张图，不会进入页面的 8/15/30 秒退避阶梯；图片的 429 仍然会让所有请求一起冷却。
- 原生浏览器引擎新增空闲自动释放：默认 5 分钟无请求即关闭标签页与调试连接，阅读器隐藏时缩短到 1 分钟，下次请求自动重连。可用 `linuxdoGuest.nativeIdleReleaseMinutes` 调整，`0` 表示不释放。**代价是重连时需要重新完成一次 Cloudflare 验证。**
- 原生引擎响应改用 `arrayBuffer()`，不再经过 `text()` 解码再编码；此前任何非 UTF-8 字节都会被替换成 U+FFFD。
- 修复原生会话泄漏：已终止的调试会话会从跟踪数组中剔除并限制上限，`stop()` 之后重新注册终止监听器。
- 原生引擎每次导航不再固定抢 3 次焦点：只在确实被 `startDebugging` 或验证页夺走焦点后才恢复，稳态导航不再执行任何 workbench 命令。
- 阅读器与验证面板改用面板级 disposable，关闭后不再滞留在 `context.subscriptions` 中；验证面板不再保留隐藏时的上下文。
- 加密分享的 60 万轮 PBKDF2 改为异步执行，不再阻塞扩展宿主；同步接口与跨平台固定向量保持不变。
- 暂停中的赛车、跳跃和贪吃蛇不再持续重绘 Canvas；游戏计时器数组不再无限增长。
- 安装包不再包含仅用于文档的截图，体积从 233 KB 降到 94 KB。
- PyCharm 版最低支持从 2024.2 降到 **2022.3**，上限提高到 2026.3。注意：构建仍在 2026.1 SDK 上完成，2022.3 兼容性为声明值，未在 2022.3 SDK 上实测。

## 0.16.0

- 新增 VS Code Integrated Browser 请求引擎：默认在 VS Code 内置 Chromium 中完成 Cloudflare challenge，并在同一浏览器会话中请求公开 JSON，避免把 Cookie、User-Agent 和浏览器指纹拆开后再次触发 403。
- 新增“自动 / VS Code 原生浏览器 / 手动参数”请求引擎切换；旧版 VS Code 或原生浏览器不可用时，自动模式才回退到已保存的手动请求档案。
- 原生会话使用独立 ephemeral 浏览器存储、精确的 `linux.do` 调试 URL 过滤和 60 KB 响应分块；排除 Cloudflare iframe、blob 和 challenge 子目标。
- 连接完成后多次尝试把焦点还给阅读器，同时保留临时 `VM...` 调试编辑器以避免部分 VS Code 版本终止 CDP 会话；关闭阅读器、清除验证或退出扩展时停止调试连接，并尽力关闭本扩展创建的原生浏览器标签；VS Code 重载后会按需建立新连接。
- 增加原生浏览器能力、Cloudflare 子目标过滤、多块 UTF-8 响应和标签清理测试；原有请求调度、缓存、分享和游戏测试保持通过。

## 0.15.1

- 修正 Cloudflare challenge 与无标记 HTTP 403 的误判：已有游客档案时不再直接提示“验证已失效”，改为 8、15、30 秒的短暂保护退避，成功一次立即清零。
- 临时保护状态与真正的 429/`Retry-After` 服务器限流分开处理，不触发本地 60 秒冷却；首次页面最多自动重试一次，已有页面和最长 6 小时缓存继续保留。
- 参数测试收到 challenge 时明确显示“本次无法判断档案失效”，不会覆盖旧档案；用户可稍后重试，或主动仅保存为未验证档案。
- 旧 SecretStorage 中的 Cookie 与 User-Agent 迁移后允许实际尝试请求，公开接口成功后自动升级为已验证档案，不再强制先重填参数。

## 0.15.0

- Cloudflare 参数改为原子游客请求档案，统一保存白名单 Cookie、User-Agent、允许的客户端提示、来源和验证状态；旧 SecretStorage 分项参数自动迁移为待验证档案。
- 验证设置页支持完整 Request Headers 及 Chrome、Edge、Brave 的 Copy as cURL；cURL 只解析不执行，并拒绝登录 Cookie、Authorization、CSRF、论坛 API 凭据和跨浏览器参数混用。
- 验证固定只测试一次 `/latest.json`；测试失败不覆盖此前有效档案，服务器冷却期间不发送测试请求。
- 移除 60 秒滑动窗口，改用平滑令牌桶：流畅每 4 秒、均衡每 5 秒、稳妥每 8 秒恢复一次请求；导航、手动续载和自动续载使用单并发优先队列。
- 重做 403/429 分类：Cloudflare challenge 直接回到验证提示，明确限流遵守 `Retry-After` 和 RateLimit 预算；无标记 403 不再伪装成 20/60 秒限流，而是报告参数或 TLS/HTTP2 指纹不兼容。
- 缓存改为列表 5 分钟、搜索 2 分钟、分类 30 分钟、主题 30 分钟、帖子续载 60 分钟及 80 条 LRU；冷却或离线时保留最长 6 小时陈旧缓存。
- 自动续载要求新的向下滚动意图，短页面不再连续请求；手动“加载更多”保持可用。
- 阅读器工具栏和活动栏新增“打开加密分享”；强密码生成后支持复制，生成分享后可反复复制分享内容或密码。
- 五款小游戏的选择页、HUD、倒计时、暂停、结果面板、控件、Canvas 和响应式样式抽取为共享 UI，VS Code 与 PyCharm 使用同一份玩法和视觉实现。

## 0.14.0

- 临时分享改为“有效期 + 分享密码”的简化流程，支持自己填写至少 12 个字符的密码或生成 20 位强密码。
- 主题、标题、生成时间和过期时间使用 AES-256-GCM 加密；密码经随机盐和 600,000 次 PBKDF2-HMAC-SHA256 派生密钥。
- 密码不写入分享内容或插件存储，旧版未加密分享内容停止导入。
- 增加 Java/Node 固定加密向量，覆盖错误密码、篡改、过期、未来时间、弱密码和密文元数据不可见。
- VS Code 请求调度改为两次短突发、约 2.2 秒补充一次的令牌节奏，并取消尚未发送的过时导航与分页请求。
- 已成功访问后出现的 403 先按临时限流冷却并逐级降速，避免立即误判为游客参数失效。

- 增加显式的 VS Code → PyCharm 与 PyCharm → VS Code 固定向量兼容测试。

## 0.8.0
